### Почему этот порядок?

1. ✅ **Раннее обнаружение проблем** - проблемы с данными видны сразу
2. ✅ **Типобезопасность** - Convex генерирует типы автоматически
3. ✅ **Легче тестировать** - изолированные части проще отлаживать
4. ✅ **Меньше рефакторинга** - правильная основа с самого начала

## 📅 Рекомендуемый порядок разработки

### Этап 1: Настройка и схема (1 час) ⚡ НАЧНИТЕ ЗДЕСЬ

**Цель**: Создать правильную основу для всего проекта

**Шаги**:
1. Инициализировать Convex проект (`npx convex dev`)
2. Создать схему БД (`convex/schema.ts`)
3. Загрузить seed данные (3 стиля)
4. **Проверить**: Queries работают, типы генерируются

**Почему сначала это?**
- Если схема неправильная - все сломается позже
- Типы генерируются автоматически, нужно проверить сразу
- Seed данные нужны для тестирования

**Риски**: Проблемы с типизацией (см. [RISK_ANALYSIS.md](./RISK_ANALYSIS.md#1-проблемы-с-типизацией-convex))

---

### Этап 2: Базовые Queries (30 минут)

**Цель**: Убедиться что данные читаются правильно

**Шаги**:
1. Создать queries для стилей
2. Создать queries для проектов
3. Создать queries для сцен
4. **Проверить**: Все queries работают, данные загружаются

**Почему дальше это?**
- Queries не меняют данные (безопасно тестировать)
- Нужны для фронтенда
- Проверяют что схема правильная

**Риски**: Ошибки аутентификации (см. [RISK_ANALYSIS.md](./RISK_ANALYSIS.md#4-ошибки-аутентификации))

---

### Этап 3: Mutations (1 час)

**Цель**: Убедиться что данные сохраняются правильно

**Шаги**:
1. Создать mutation для создания проекта
2. Создать mutation для создания сцен
3. Создать mutations для обновления сцен
4. **Проверить**: Данные сохраняются, права доступа работают

**Почему дальше это?**
- Mutations меняют данные (нужно проверить права доступа)
- Нужны для создания проектов
- Основа для actions

**Риски**: Ошибки прав доступа (см. [RISK_ANALYSIS.md](./RISK_ANALYSIS.md#4-ошибки-аутентификации))

---

### Этап 4: Actions для внешних API (2 часа)

**Цель**: Интегрировать AI провайдеров

**Шаги**:
1. Создать action для генерации storyboard (OpenRouter)
2. Создать action для генерации изображений (Replicate)
3. Создать action для генерации аудио (ElevenLabs **НАПРЯМУЮ**)
4. **Проверить**: Все API вызываются, файлы загружаются в Storage

**Почему дальше это?**
- Actions могут делать внешние запросы
- Нужны для core функциональности
- Самая сложная часть (много потенциальных ошибок)

**Риски**: 
- Ошибки парсинга AI ответов (см. [RISK_ANALYSIS.md](./RISK_ANALYSIS.md#2-ошибки-парсинга-ai-ответов))
- Проблемы с Storage (см. [RISK_ANALYSIS.md](./RISK_ANALYSIS.md#3-проблемы-с-storage))
- Timeout внешних API (см. [RISK_ANALYSIS.md](./RISK_ANALYSIS.md#5-timeout-внешних-api))

---

### Этап 5: Frontend интеграция (2 часа)

**Цель**: Связать backend с UI

**Шаги**:
1. Настроить ConvexProvider
2. Интегрировать queries в компоненты
3. Интегрировать mutations и actions
4. **Проверить**: UI обновляется, real-time работает

**Почему дальше это?**
- Frontend зависит от backend
- Нужно проверить что все работает вместе
- Real-time обновления нужно тестировать

**Риски**: Проблемы с real-time (см. [RISK_ANALYSIS.md](./RISK_ANALYSIS.md#6-проблемы-с-real-time-обновлениями))

---

### Этап 6: Полировка (1-2 часа)

**Цель**: Улучшить UX и обработать ошибки

**Шаги**:
1. Добавить error boundaries
2. Улучшить loading states
3. Добавить retry механизмы
4. **Проверить**: Все ошибки обрабатываются, UX приятный

**Почему в конце?**
- Основная функциональность уже работает
- Улучшения, а не критичные функции
- Можно пропустить если нет времени

## 🚨 Критические моменты

### 1. ElevenLabs НАПРЯМУЮ ⚠️

**Проверка**: В логах должно быть:
```
🎵 TTS: Calling ElevenLabs API directly
URL: https://api.elevenlabs.io/v1/text-to-speech/{voiceId}
```

**НЕ должно быть**:
- ❌ Proxy URL
- ❌ VoicerAPI
- ❌ Любые посредники

**Где проверить**: `convex/functions/audio.ts` - action `generateAudio`

---

### 2. Типизация Convex ⚠️

**Проверка**: После каждого изменения схемы:
1. Сохраните `schema.ts`
2. Проверьте что `convex dev` перегенерировал типы
3. Проверьте что нет ошибок в IDE
4. Проверьте что `_generated/api.d.ts` обновился

**Если ошибки**: См. [RISK_ANALYSIS.md](./RISK_ANALYSIS.md#1-проблемы-с-типизацией-convex)

---

### 3. Storage только в Actions ⚠️

**Правило**: `ctx.storage.store()` можно использовать ТОЛЬКО в `action`, НЕ в `mutation`!

**Правильно**:
```typescript
export const generateImage = action({
  handler: async (ctx, args) => {
    const storageId = await ctx.storage.store(blob); // ✅ OK
  }
});
```

**Неправильно**:
```typescript
export const createProject = mutation({
  handler: async (ctx, args) => {
    const storageId = await ctx.storage.store(blob); // ❌ ERROR!
  }
});
```
