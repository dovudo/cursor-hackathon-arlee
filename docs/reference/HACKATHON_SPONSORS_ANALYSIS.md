## 📊 Анализ продуктов спонсоров

### 1. **ElevenLabs** ✅ УЖЕ ИСПОЛЬЗУЕТСЯ

**Что это**: AI-платформа для генерации речи (TTS), клонирования голосов, транскрипции

**Текущее использование в проекте**:
- ✅ Уже интегрирован в основной проект
- ✅ Используется для генерации аудио-озвучки сцен
- ⚠️ В основном проекте используется через proxy (`proxy-elevenlabs`)

**Для MVP**:
- ✅ **Использовать НАПРЯМУЮ** (без proxy) - это требование хакатона
- ✅ Прямой вызов API: `https://api.elevenlabs.io/v1/text-to-speech/{voiceId}`
- ✅ Модель: `eleven_multilingual_v2` (поддержка русского языка)
- ✅ Простая интеграция в Edge Function `generate-audio`

**Преимущества**:
- Высокое качество голосов
- Поддержка множества языков
- Быстрая генерация
- Простой REST API

**Рекомендация**: ✅ **ИСПОЛЬЗОВАТЬ** - уже есть в проекте, просто убрать proxy

---

### 2. **Convex** 🔄 РЕКОМЕНДУЕТСЯ К РАССМОТРЕНИЮ

**Что это**: Реактивная база данных с TypeScript queries, real-time обновлениями, serverless функциями

**Сравнение с Supabase**:

| Функция | Supabase | Convex |
|---------|----------|--------|
| База данных | PostgreSQL (SQL) | Document-relational (TypeScript) |
| Real-time | Supabase Realtime (WebSockets) | Автоматический (встроен в queries) |
| Serverless функции | Edge Functions (Deno) | Actions/Mutations (TypeScript) |
| Хранение файлов | Supabase Storage | Встроенное Storage API |
| Аутентификация | Supabase Auth | Интеграция с внешними провайдерами |
| Типизация | Ручная (TypeScript) | Автоматическая (генерируется) |
| Реактивность | Ручная подписка | Автоматическая (queries) |

**Преимущества Convex для MVP**:
- ✅ **Автоматическая реактивность** - не нужен polling или ручная подписка
- ✅ **TypeScript-first** - все в TypeScript, автоматическая типизация
- ✅ **Проще для быстрой разработки** - меньше boilerplate кода
- ✅ **Встроенный real-time** - queries автоматически обновляются
- ✅ **Простое хранение файлов** - `ctx.storage.store()` вместо отдельного сервиса

**Недостатки Convex**:
- ⚠️ **Новая платформа** - меньше документации и примеров
- ⚠️ **Меньше контроля** - меньше гибкости чем PostgreSQL
- ⚠️ **Миграция** - нужно переписать все Edge Functions на Convex Actions/Mutations

**Рекомендация**: 
- 🔄 **РАССМОТРЕТЬ** для нового MVP (если есть время на изучение)
- ⚠️ **НЕ РЕКОМЕНДУЕТСЯ** если нужно быстро (уже есть работающий Supabase код)

**Когда использовать Convex**:
- Если хотите продемонстрировать использование продукта спонсора
- Если есть время на изучение (1-2 часа)
- Если нужна максимальная простота real-time обновлений

**Когда остаться на Supabase**:
- Если нужно быстро (уже есть код)
- Если нужен полный контроль над SQL
- Если команда знакома с Supabase

### 3. **Superagent** 🤔 МОЖЕТ БЫТЬ ПОЛЕЗЕН

**Что это**: Фреймворк для создания AI агентов и защищенный proxy для AI API

**Возможности**:
- ✅ **AI Firewall** - защита от prompt injection, валидация tool calls
- ✅ **Unified Observability** - мониторинг всех AI запросов
- ✅ **Proxy для AI API** - единая точка входа для всех AI провайдеров
- ✅ **Agent Framework** - создание AI агентов с инструментами

**Применение для MVP**:
- 🤔 **Опционально**: Можно использовать как proxy для OpenRouter/Replicate
- ✅ **Полезно**: Если нужно добавить защиту от prompt injection
- ⚠️ **Не критично**: Для MVP можно обойтись без него

**Рекомендация**: 
- ⚠️ **ОПЦИОНАЛЬНО** - можно добавить позже для безопасности
- ✅ **НЕ ОБЯЗАТЕЛЬНО** для MVP - добавляет сложность

**Если использовать**:
```typescript
// Вместо прямого вызова OpenRouter
const response = await fetch('YOUR_SUPERAGENT_PROXY_URL/chat/completions', {
  headers: {
    'Authorization': `Bearer ${OPENROUTER_API_KEY}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({ model: 'gpt-4', messages: [...] })
})
```

## 🎯 Рекомендации по архитектуре MVP

### Вариант 1: Быстрый MVP (Supabase) ⚡ РЕКОМЕНДУЕТСЯ

**Стек**:
- ✅ **Backend**: Supabase (PostgreSQL + Edge Functions)
- ✅ **Frontend**: Next.js 15 + React Context
- ✅ **AI**: OpenRouter (GPT-4/Gemini) + Replicate (FLUX) + ElevenLabs (напрямую)
- ✅ **Real-time**: Polling (проще чем Realtime для MVP)

**Преимущества**:
- ✅ Уже есть рабочий код в проекте
- ✅ Быстрая реализация (6-7 часов)
- ✅ Знакомая технология
- ✅ ElevenLabs напрямую (требование хакатона)

**Недостатки**:
- ⚠️ Не использует Convex (продукт спонсора)

**Время реализации**: 6-7 часов

---

### Вариант 2: MVP с Convex 🔄 АЛЬТЕРНАТИВА

**Стек**:
- ✅ **Backend**: Convex (Database + Actions/Mutations)
- ✅ **Frontend**: Next.js 15 + Convex React hooks
- ✅ **AI**: OpenRouter + Replicate + ElevenLabs (напрямую)
- ✅ **Real-time**: Автоматический (встроен в Convex)

**Преимущества**:
- ✅ Использует продукт спонсора (Convex)
- ✅ Автоматический real-time (не нужен polling)
- ✅ TypeScript-first подход
- ✅ Меньше boilerplate кода
- ✅ ElevenLabs напрямую (требование хакатона)

**Недостатки**:
- ⚠️ Нужно переписать весь backend код
- ⚠️ Время на изучение Convex (1-2 часа)
- ⚠️ Больше времени на реализацию (8-10 часов)

**Время реализации**: 8-10 часов (с учетом изучения)

---

### Вариант 3: Гибридный (Supabase + Convex) 🤔 СЛОЖНО

**Стек**:
- ✅ **Backend**: Supabase (БД) + Convex (real-time queries)
- ✅ **Frontend**: Next.js 15 + Convex React hooks
- ✅ **AI**: OpenRouter + Replicate + ElevenLabs

**Преимущества**:
- ✅ Использует Convex частично
- ✅ Сохраняет существующий код Supabase

**Недостатки**:
- ⚠️ Сложная архитектура (две платформы)
- ⚠️ Больше времени на интеграцию
- ⚠️ Не рекомендуется для MVP

**Время реализации**: 10+ часов
